Setup · Your cloud on your laptop

Floci, locally or in a Codespace

🧰

Your AWS for this course runs on your laptop, or in a Codespace if your laptop can't.

We use Floci, an open-source AWS emulator. Same AWS CLI, same commands, same APIs as real AWS, running in Docker.
No timer, no budget, no account to share: your group's infra lives as long as you want, and anyone in the group can rebuild it from your repo.

🎯 What you get

  • A full AWS-like cloud on http://localhost:4566: IAM, S3, EC2, VPC, ELB, ECS, ECR, RDS, Lambda, CloudWatch, SNS, SQS, CloudFront, CloudFormation and more.
  • Real enforcement where it matters: IAM policies are checked (you'll see real AccessDenied), security groups really filter traffic between your containers.
  • Real things behind the API: an EC2 instance is a real Linux container, RDS is a real PostgreSQL, ECS runs your real image.

🧭 Pick your way in

Way A, your laptop (recommended if Docker works on it)

  1. Install Docker Desktop (Mac, Windows) or Docker Engine (Linux, your user in the docker group). Rootless Docker is not supported.
  2. Install the AWS CLI v2 and git.
  3. On Windows: use PowerShell for everything, with Git for Windows and the AWS CLI .msi installer. The course gives you a PowerShell version of every command and every script (env.ps1, doctor.ps1, check.ps1...), look for the 🪟 Windows tab.
  4. Get the starter (next section), then in its folder:
# Start Floci (the first time pulls about 100 MB)
docker compose up -d

# Point the AWS CLI at Floci, in every new terminal
source env.sh

# Check your setup, everything should say OK
./doctor.sh
# Allow the starter's scripts to run (once per machine)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned -Force

# Start Floci (the first time pulls about 100 MB)
docker compose up -d

# Point the AWS CLI at Floci, in every new PowerShell window
. .\env.ps1

# Check your setup, everything should say OK
.\doctor.ps1

Way B, a GitHub Codespace (a Linux machine in your browser, free with your GitHub account)

  1. Open your group repo on GitHub → Code → Codespaces → Create codespace on main.
  2. Wait for VS Code to open. Floci starts by itself, Docker can take a minute after the codespace wakes up.
  3. In the terminal: source env.sh && ./doctor.sh.
  4. Stop the codespace when you leave (it auto-stops after 30 min idle). The free plan gives about 60 hours a month on 2 cores, plenty for this course.
⚠️

Both ways give exactly the same results, the checks print the same lines.
Don't mix them inside one group without your repo: the repo is what you share, not a laptop.

👀 The Floci UI

After the commands, the milestones ask you to go look at what you built.
You get a hint first. Try it, then unfold 📸 to compare with the screenshot.

  1. Open the Floci UI launcher once each time you start Floci. It starts the UI and sends you to port 4500.
  2. After that, the link under each screenshot opens the same screen in your Floci.
☁️

In a Codespace, the localhost links don't work from your browser. In the Ports tab, open port 4566 and add /_floci/ui to the address to start the UI, then add port 4500 and open it. Use the sidebar, or copy the end of the link's path after that address. Keep both ports private.

It's a resource explorer, not the AWS console, so some steps have a 🆚 toggle with the real one. Look with the UI, build with commands: what you click isn't in your repo, so a rebuild loses it.

🔒 Close Floci to the network

🚨

Got the starter before November 23? Do this before anything else, on each laptop that runs Floci.

The first starter let anyone on the same Wi-Fi use your Floci, read what's in it and start containers on your machine. The fix takes 2 minutes and keeps your resources. Don't run wipe, you don't need it.

Can't do it right now? Quit Docker Desktop (Linux: stop every Floci container with docker stop $(docker ps -q --filter name=floci)). docker compose down is not enough, it leaves containers open.

Fix 1: go to your group folder, the one you run docker compose up -d from (change the path), with Docker running. The second command must find both (Windows: True twice). If it doesn't, you're in the wrong folder: stop and find the right one.

cd path/to/my-group
ls -d docker-compose.yml data
cd path\to\my-group
Test-Path docker-compose.yml, data

Fix 2: take the fixed file and restart. It downloads the file, removes the old UI container ("No such container" is fine) and restarts Floci on the same data.

curl -fsSL https://raw.githubusercontent.com/ricoleabricot/puff/main/starter/docker-compose.yml -o docker-compose.yml
docker rm -f floci-aws-ui
docker compose up -d
curl.exe -fsSL https://raw.githubusercontent.com/ricoleabricot/puff/main/starter/docker-compose.yml -o docker-compose.yml
docker rm -f floci-aws-ui
docker compose up -d

Fix 3: check. Wait 20 seconds, then paste the whole block. It lists any Floci port other machines can reach, you want CLOSED.

RUNNING=$(docker ps --format '{{.Names}} {{.Ports}}' | grep floci)
OPEN=$(echo "$RUNNING" | grep -E '0\.0\.0\.0:|\[::\]:')
if [ -z "$RUNNING" ]; then echo "NOT RUNNING: go back to fix 2"
elif [ -n "$OPEN" ]; then echo "STILL OPEN:"; echo "$OPEN"
else echo "CLOSED"; fi
$RUNNING = @(docker ps --format '{{.Names}} {{.Ports}}' | Select-String 'floci')
$OPEN = @($RUNNING | Select-String '0\.0\.0\.0:|\[::\]:')
if ($RUNNING.Count -eq 0) { "NOT RUNNING: go back to fix 2" }
elseif ($OPEN.Count -gt 0) { "STILL OPEN:"; $OPEN | ForEach-Object { "$_" } }
else { "CLOSED" }
  • CLOSED: you're safe, go to fix 5.
  • STILL OPEN with i- followed by letters and digits in the name: a VM from course 2 is still running, do fix 4.
  • STILL OPEN with floci or floci-aws-ui: fix 2 ran in the wrong folder or the download failed, start again from fix 1.
  • Anything else: quit Docker and show me the output.

Fix 4: only if a VM is still open. It removes the course 2 VMs and nothing else: your app, database and data aren't touched.

for c in $(docker ps -aq --filter name='floci-aws-(ec2|ec2-fwd|sg)-i-'); do docker rm -f "$c"; done
docker ps -aq --filter 'name=floci-aws-(ec2|ec2-fwd|sg)-i-' | ForEach-Object { docker rm -f $_ }

Then run fix 3 again, you want CLOSED.

Fix 5: one member only pushes the fixed file, so nobody gets the old one back from your repo.

git add docker-compose.yml
git commit -m "Close Floci to the network" -- docker-compose.yml
git push
git add docker-compose.yml
git commit -m "Close Floci to the network" -- docker-compose.yml
git push

The other members still do fixes 1 to 4 on their laptop, then take the pushed file:

git checkout -- docker-compose.yml
git pull
docker compose up -d
git checkout -- docker-compose.yml
git pull
docker compose up -d
🧯 Linux, Codespaces, or something looks strange
  • Linux: docker version --format '{{.Server.Version}}' must be 28 or more. Older Docker Engines let machines on the same network reach 127.0.0.1 ports, so update it.
  • Codespace: it isn't on the room's Wi-Fi, but do the fix too so your repo has the right file, and keep every forwarded port Private.
  • A container or an image in docker ps -a that you don't recognize: quit Docker, don't delete it, show it to me.

🧯 If it doesn't work

  • doctor.sh says Docker isn't running: start Docker Desktop. In a Codespace, wait a minute and retry.
  • Windows: "running scripts is disabled on this system": run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, then reopen PowerShell.
  • Windows: curl asks strange questions or prints an object: in PowerShell 5.1 curl is a different command, always type curl.exe.
  • Windows: an AWS command fails on a JSON argument: PowerShell 5.1 eats the quotes. The Windows tabs always put JSON in a file and pass file://name.json, do the same.
  • Windows: a script runs but check.ps1 says set GROUP first: set it in this window, $env:GROUP = "g07".
  • Port 80 or 4566 already in use: another Floci or web server is running, docker ps and stop it.
  • The CLI talks to real AWS or asks for a profile: you forgot source env.sh (Windows: . .\env.ps1) in this terminal.
  • docker push fails with "HTTP response to HTTPS client": push to $REGISTRY/... (localhost:5100), not to the ECR URI.
  • Something is in a weird state: ./wipe.sh then rebuild with ./infra/deploy.sh. That's exactly why the script exists.
  • Floci itself can be wrong sometimes, it's an emulator. If you're sure your command is right, ask me, a bug report counts as a good find.
