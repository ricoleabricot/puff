Setup · Your cloud on your laptop

Floci, locally or in a Codespace

🧰

Your AWS for this course runs on your laptop, or in a Codespace if your laptop can't.

We use Floci, an open-source AWS emulator. Same AWS CLI, same commands, same APIs as real AWS, running in Docker.
No timer, no budget, no account to share: your group's infra lives as long as you want, and anyone in the group can rebuild it from your repo.

🎯 What you get

  • A full AWS-like cloud on http://localhost:4566: IAM, S3, EC2, VPC, ELB, ECS, ECR, RDS, Lambda, CloudWatch, SNS, SQS, CloudFront, CloudFormation and more.
  • Real enforcement where it matters: IAM policies are checked (you'll see real AccessDenied), security groups really filter traffic between your containers.
  • Real things behind the API: an EC2 instance is a real Linux container, RDS is a real PostgreSQL, ECS runs your real image.

🧭 Pick your way in

Way A, your laptop (recommended if Docker works on it)

  1. Install Docker Desktop (Mac, Windows with WSL2) or Docker Engine (Linux, your user in the docker group). Rootless Docker is not supported.
  2. Install the AWS CLI v2 and git.
  3. Get the starter (next section), then in its folder:
docker compose up -d       # starts Floci, first time pulls ~100 MB
source env.sh              # points the AWS CLI at Floci, do it in every new terminal
./doctor.sh                # everything should say OK

Way B, a GitHub Codespace (a Linux machine in your browser, free with your GitHub account)

  1. Open your group repo on GitHub → Code → Codespaces → Create codespace on main.
  2. Wait for VS Code to open. Floci starts by itself, Docker can take a minute after the codespace wakes up.
  3. In the terminal: source env.sh && ./doctor.sh.
  4. Stop the codespace when you leave (it auto-stops after 30 min idle). The free plan gives about 60 hours a month on 2 cores, plenty for this course.
⚠️

Both ways give exactly the same results, the checks print the same lines.
Don't mix them inside one group without your repo: the repo is what you share, not a laptop.

📦 Get the starter into your group repo

One member does this once, then the others clone the group repo.

git clone https://github.com/ricoleabricot/puff.git /tmp/puff
mkdir my-group && cp -r /tmp/puff/starter/. my-group/ && cd my-group
git init -b main && git add . && git commit -m "Puff starter"
# create an empty repo on GitHub (private is fine), then:
git remote add origin https://github.com/<you>/<repo>.git && git push -u origin main

Then everyone sets the group id once per terminal, it prefixes every resource name:

export GROUP=g07          # your group number, two digits

🧪 Your first commands

aws sts get-caller-identity          # account 000000000000, that's Floci
aws ec2 describe-regions --query 'length(Regions)'
aws s3api create-bucket --bucket $GROUP-hello
aws s3 ls

Floci has a small web UI too: http://localhost:4566/_floci/ui. It's a resource explorer, not the AWS console. The course pages show real console screenshots where it matters.

🔍 Floci vs real AWS, what to keep in mind

TopicOn FlociOn real AWS
Account, credentialsAccount 000000000000, keys test/test are the adminYour org's accounts, SSO, never long-lived admin keys
Container imagesPush to localhost:5100/<repo>, it shows up in ECRPush to <account>.dkr.ecr.<region>.amazonaws.com/<repo>
NetworkSecurity groups filter traffic between containers. Routes, NAT and internet gateways exist in the API but don't route anythingEverything routes for real
Load balancerLives inside Floci, answers on http://<alb-dns>/ (port 80 of your machine)Its own managed nodes in your subnets
ScalingNothing scales on its own. You'll build your own autoscaler with an alarm and a LambdaTarget tracking, scheduled actions
EmailNot delivered, use an SQS queue as your pagerSNS emails, Slack, PagerDuty
CostFreeEvery hour counts, you'll price your stack in course 6

🧯 If it doesn't work

  • doctor.sh says Docker isn't running: start Docker Desktop. In a Codespace, wait a minute and retry.
  • Port 80 or 4566 already in use: another Floci or web server is running, docker ps and stop it.
  • The CLI talks to real AWS or asks for a profile: you forgot source env.sh in this terminal.
  • docker push fails with "HTTP response to HTTPS client": push to $REGISTRY/... (localhost:5100), not to the ECR URI.
  • Something is in a weird state: ./wipe.sh then rebuild with ./infra/deploy.sh. That's exactly why the script exists.
  • Floci itself can be wrong sometimes, it's an emulator. If you're sure your command is right, ask me, a bug report counts as a good find.
