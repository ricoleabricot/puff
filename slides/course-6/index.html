        Infrastructure as code

        The recipe, not the cake

        Lose the cake, you bake another. Lose the recipe, you're guessing.

          Four things get better

          • You see driftThe tool tells you when reality differs from the code, before something breaks
          • Changes get reviewedA firewall change becomes a pull request a classmate reads, with a history of who changed what
          • Copies are identicalTest and the real thing come from the same template, so "it worked in test" means something
          • Recovery gets simpleLose a region, redeploy the files somewhere else. No rebuilding from screenshots at 3:00

            Write the steps, or write the end result

            Imperative

            A bash script: create-vpc, then create-subnet, then create-nat-gateway. Crashes halfway? You find where by hand

            Declarative

            "There is a VPC 10.0.0.0/16 with four subnets." The tool works out the steps itself

                A template has three sections

                What it holds Example
                ParametersInputs given at deploy timeLogin, NamePrefix
                ResourcesThe only required one: logical ID, Type, PropertiesAssetsBucket, an AWS::S3::Bucket
                OutputsValues shown once it's builtBucketArn, VpcId

                !Ref gives the ID, !GetAtt one attribute. Every !Ref is also a "build that first".

                  Three stack features you'll use for real

                  • Change setsA preview of what gets added, modified or removed, before anything happens
                  • Automatic rollbackA deploy fails halfway, everything goes back. No half a Puff
                  • Drift detectionCompares each resource with the template and flags anything changed by hand

                                                      FinOps

                                                      Whoever picks the server size is spending money

                                                      When your group defends its Puff, "what does it cost?" will be one of my first questions.

                                                        The usual cost surprises

                                                        • NAT gateway dataPer hour and per GB, that's why S3 traffic takes the free gateway endpoint
                                                        • Idle resourcesA NAT, a load balancer or a database costs the same with zero visitors
                                                        • Oversized serversAn m5.2xlarge picked "to be safe", at 4% CPU for a year
                                                        • Data going outTo the internet, across AZs and regions. Coming in is free
                                                        • Public IPv4Every address, the NAT's and the ALB's, billed per hour

                                                          What Puff costs per month

                                                          Assumption Per month
                                                          EC2 t3.micro × 2730 h each~$15
                                                          RDS db.t3.micro, single-AZ730 h + 20 GB~$16
                                                          Application Load Balancer730 h + ~1 LCU~$22
                                                          NAT gateway730 h + a few GB~$33
                                                          Public IPv4 × 3NAT EIP + 2 ALB addresses~$11
                                                          Total, with disks, S3 and alarmsus-east-1, low traffic~$100

                                                          NAT, ALB and public IPs are two thirds of the bill. The two API servers, a sixth.
