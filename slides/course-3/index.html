      Recap

      Last session, everything was public

      The database, the API on port 8080, SSH. Only a password stood between the internet and our data.

        A VPC is your own gated neighborhood

        A private network in one Region, across all its AZs. Nothing gets in unless you open a way in.

          10.0.0.0/16

          Puff's range. The first 16 bits are fixed, the last 16 are yours: 65,536 addresses.

            Counting addresses

            Size Addresses Where you meet it
            /1665,536Puff's VPC, the largest AWS allows
            /204,096Each of Puff's four subnets
            /24256, 251 usableA classic subnet, AWS keeps 5
            /2816, 11 usableThe smallest VPC

            Private IPs cost nothing, so Puff's /20 subnets are far bigger than it needs.

              Ranges that will collide one day

              • Home routers192.168.0.0/24 or 192.168.1.0/24
              • DockerThe default bridge on 172.17.0.0/16
              • CompaniesA lot of corporate networks somewhere in 10.0.0.0/8
              • AWSRefuses to connect overlapping VPCs. Fixing it later means rebuilding the network
                Weeks

                At Alan, networks that may need to talk get non-overlapping ranges, decided before the network exists. Changing one later takes weeks.

                  There's no "public" checkbox

                  A subnet is public when its route table sends 0.0.0.0/0 to an Internet Gateway. Private when it doesn't.

                    Two route tables, one difference

                    Destination Public Private
                    10.0.0.0/16locallocal
                    0.0.0.0/0igw-... Internet Gatewaynat-... NAT gateway
                    S3 prefix list pl-...vpce-... endpointvpce-... endpoint

                    Don't trust a subnet's name. Open its route table and look where 0.0.0.0/0 goes.

                                            A private path to AWS

                                            Gateway endpoint

                                            S3 and DynamoDB only. A line in the route table, free

                                            Interface endpoint

                                            Most other services. A network card in your subnet, billed per hour and per GB

                                              Four ways to link networks, small to big

                                              • VPC peeringTwo VPCs, free to set up. It doesn't chain: A to B, B to C, A still can't reach C
                                              • Transit GatewayA hub every VPC and VPN connects to once, like a roundabout
                                              • Site-to-Site VPNAn encrypted tunnel over the internet to an office. Up in an hour
                                              • Direct ConnectA private physical cable from a data center into AWS. Takes weeks

                                                Which one, when

                                                Situation Use Why
                                                Two or three VPCs need to talkVPC peeringSimple and free
                                                Ten VPCs across accounts, plus an officeTransit GatewayOne connection per network, one place for routing
                                                Office needs AWS this weekSite-to-Site VPNFast, encrypted, cheap
                                                Terabytes a day, steady speedDirect Connect, VPN as backupPredictable speed, cheaper at volume

                                                None of them works with overlapping ranges. The IP plan keeps all four open.
